## 0. 이 문서를 받은 사람이 할 일

이 작업은 이미 **배포까지 끝났습니다.** 그래서 검토의 목적은 "잘했나"가 아니라
**"공개된 화면에 틀린 것이 남아 있나"** 입니다. 틀린 것을 찾아 주세요.

이 프로젝트의 값어치는 예쁜 문장이 아니라 **근거를 댈 수 있다는 것**에 있습니다.
따라서 가장 무거운 결함은 이 순서입니다.

1. **화면에 나가는 거짓** — 교재가 다루는 단원을 안 다룬다고 하거나, 안 다루는 것을 다룬다고 하는 것
2. **근거 없는 주장** — 출판사가 하지 않은 말을 출판사 말처럼 적은 것
3. **규칙과 설명의 불일치** — 화면이 "이렇게 이었습니다"라고 말한 것과 코드가 실제로 하는 일이 다른 것
4. **재현 불가** — 같은 입력으로 같은 결과를 다시 만들 수 없는 것

### 조사 규칙 (반드시 지킬 것)

- **웹 조사는 항상 `grok`을 씁니다.** 예: `grok -p "예스24에서 ○○ 상품 페이지 URL을 찾아 주세요"`
- grok이 준 답을 **그대로 결론으로 쓰지 마세요.** 반드시 본인이 그 URL을 직접 열어(fetch) 대조한 뒤에만 결론에 넣습니다. 이 작업 내내 지킨 규칙이고, 검토도 같은 기준으로 합니다.
- **교보문고는 쓰지 않습니다.** 봇 차단으로 본문이 2.3KB만 옵니다. 예스24만 씁니다.
- 커뮤니티·블로그·나무위키의 난이도 평가("쎈C보다 RPM이 낮다" 같은 것)는 **근거가 아닙니다.** 발견해도 반영 대상이 아니라 기록 대상입니다.
- AI가 출처 없이 한 말은 근거가 아닙니다. 본인의 판단도 마찬가지입니다.

## 1. 이 프로젝트가 무엇인가

초1~고1 수학 교육과정 **110개 단원**을 하나의 지도로 잇는 정적 웹사이트입니다.
단원 사이는 서술이 아니라 **단원 ID 참조(`prereq`)** 로 이어져 있어, 끊긴 연결과
거꾸로 된 연결을 테스트로 잡을 수 있습니다.

이번 작업은 그 지도에 **시중 교재의 목차를 붙이는** 일입니다.
"막힌 단원을 찾았다면 그다음은 어느 교재 몇 장을 펴야 하는가"에 답하려는 것입니다.

### 2-2. 고친 것 — 화면에 나가던 잘못된 표시

이것이 이번 작업의 핵심입니다. **전에 배포된 화면에 거짓이 있었습니다.**

1. **수학의 정석 공통수학2가 `0/13장`으로 보였다.**
   "한 단원에는 한 장만 붙는다"는 옛 규칙 때문. 고1은 지도의 단원 하나가 교재의
   **대단원** 하나(`도형의 방정식` 안에 평면좌표·직선·원·도형의 이동)라서, 첫 장 말고는
   전부 잘려 나갔다. 정석이 공통수학2를 안 다루는 것처럼 읽혔다.
   → 한 단원에 여러 장이 붙을 수 있게 했다.

2. **일품 공통수학2의 집합 세 장이 `도형의 방정식`에 붙어 있었다.**
   그 책 목차에 집합 단원의 대단원이 `Ⅱ. 방정식`으로 적혀 있다(서점/출판사 표기 오류).
   `방정식`이 `도형의 방정식` 안에 들어가서 걸렸다.
   → 한 단원을 두 대단원이 가리키면 확실한 쪽만 남긴다.

3. **자이스토리의 장 수가 부풀어 있었다(21장 → 실제 11장).**
   예스24 목차가 뒤쪽 모의고사 색인에 같은 목록을 한 번 더 싣는다.
   → 같은 제목이 다시 나오면 버린다.

4. **예스24의 `큐브 개념 초등 수학 4-1` 페이지에 3-1 목차가 실려 있다.**
   (덧셈과 뺄셈·평면도형·나눗셈·곱셈·길이와 시간·분수와 소수 = 초3-1 내용)
   서점 쪽 오류. 그대로 실으면 `평면도형 → 평면도형의 이동` 같은 거짓 연결이 생긴다.
   → 그 학기 단원과 하나도 안 맞고 다른 학기와 맞으면 그 권을 버린다. 지금 걸리는 것은 이 한 권뿐.
   **화면에서 큐브수학 개념의 초4-1 칸이 비어 있는 것은 이 때문이고, 의도된 것이다.**

5. **대단원 표기 세 가지를 다 인식하게 했다.**
   `Ⅰ. 도형의 방정식`(정석·쎈) · `Ⅰ 기본 도형`(자이스토리) · `Ⅰ도형의 방정식`(수력충전)

6. **짧은 목차가 통째로 빠지고 있었다.**
   자이스토리 공통수학1과 체크체크 중3-2는 대단원만 네댓 줄 실려 있어, 글자 수 기준(40자)에
   걸려 수집에서 빠졌다. 줄 수 기준(2줄 이상)으로 바꿨다.

7. **단원 제목 앞의 숫자를 장 번호로 오인해 지우고 있었다.** (커밋 `c4d4917`)
   `9까지의 수` → `까지의 수`, `50까지의 수` → `까지의 수`. 둘이 같은 문자열이 되어
   구별되지 않았고, 초1의 그 두 단원에 교재가 하나도 안 붙었다.
   → 숫자 뒤에 점이나 빈칸이 있을 때만 장 번호로 본다.
   **이 결함은 초1·초2를 넣으면서 처음 드러났다. 비슷한 것이 더 있는지가 검토 항목이다.**

### 2-3. 그 밖에

- 수집 표(`data/books/*.tsv`)와 목차 캐시를 **저장소 안으로 옮겼다.** 전에는 임시 폴더에만 있어

- `/books` 화면의 "억지로 잇지 않았습니다" 설명을 실제 규칙대로 고쳤다.

## 3. 지금 잇는 규칙 (검토의 중심)

`scripts/build-books.mjs`. 권마다 아래를 순서대로 한다.

```
0) 줄을 읽어 대단원(part)과 장 제목을 나눈다
   · 로마숫자로 시작하면 대단원
   · 같은 제목이 다시 나오면 버린다
1) [방어] 그 학기 단원과 강하게 맞는 장이 0개인데
   다른 학기와는 3개 이상 맞으면 → 이 권을 통째로 버린다
2) 대단원 이름을 단원에 미리 맞춰 둔다
   · 한 단원을 두 대단원이 가리키면 확실한 쪽만 남긴다
3) 장마다 아래 순서로 내려간다. 위에서 붙으면 아래는 안 본다
   a. 장 제목 ↔ 단원 이름   (같음 / 단원 이름을 품음 / 단원 이름 안에 들어감)
      → 이 방법으로 붙은 단원은 그 권에서 **한 장만** 갖는다
   b. 장 제목이 그 단원의 **핵심어(keywords)** 를 통째로 품음
   c. 장이 속한 **대단원**이 그 단원과 맞음
      → b·c로는 한 단원에 **여러 장**이 붙어도 된다
   · 모의고사·정답·해설·찾아보기·부록·워크북이 들어간 줄은 잇지 않는다
```

### 실제로 어느 규칙이 얼마나 일했나 (현재 1570개)

| 규칙 | 연결 수 |
| --- | --- |
| a. 장 제목 | 약 1000 |
| b. 핵심어 | 약 490 |
| c. 대단원 | 약 80 |

### 검토자가 특히 따져 봐야 할 판단

- **b(핵심어) 규칙이 정당한가.** 핵심어는 우리가 그 단원에 적어 둔 범위다.
  그래서 "유리함수의 그래프"라는 장은 "함수와 그래프" 단원 안이라고 말할 수 있다.
  하지만 이것은 **우리 데이터로 우리 연결을 정당화하는 것**이기도 하다.
  화면의 설명문("핵심어와 견줍니다")과 맞는가? 잘못 붙은 사례가 있는가?
- **두 글자 핵심어를 받는 것이 위험한가.** `순열`·`조합`·`행렬` 같은 두 글자를 받아야
  정석의 "17. 순열과 조합", "18. 행렬의 뜻"이 붙는다. 반대로 우연히 겹칠 위험도 있다.
- **a 규칙에서만 "한 장만"인 것이 일관성 있는가.**
- **1)의 방어선이 놓치는 경우가 있는가.** 지금 걸리는 것은 큐브 4-1 하나뿐이다.

### 4-2. 상품 주소가 맞는지 다시 대조하기

```bash

    await new Promise(r => setTimeout(r, 800));
  }
});'
```

### 4-3. 근거가 안 보이는 연결 찾기 (작업자가 쓴 자체 점검)

```bash
node --experimental-strip-types -e '
const { BOOK_VOLUMES } = await import("./content/books.ts");
const { unitById } = await import("./content/index.ts");
const norm = (t) => t
  .replace(/^(?:[IVX]+\s*[.．]|[ⅠⅡⅢⅣⅤⅥⅦⅧⅨⅩ]+\s*[.．]?)\s*/i, "")
  .replace(/^\d+\s*[.．]\s*|^\d+\s+/, "")
  .replace(/\s*\d+\s*$/, "")
  .replace(/[()（）⑴⑵⑶⑷【】\[\]]/g, "")
  .replace(/[·ㆍ・]/g, "").replace(/\s+/g, "").trim();
let n = 0;
for (const v of BOOK_VOLUMES) for (const c of v.chapters) {
  if (!c.unitId) continue;
  const u = unitById.get(c.unitId), t = norm(c.title), ut = norm(u.title);
  if (t.includes(ut) || ut.includes(t)) continue;
  if (c.part && (norm(c.part).includes(ut) || ut.includes(norm(c.part)))) continue;
  if (u.keywords.some(k => norm(k).length >= 2 && t.includes(norm(k)))) continue;
  n++; console.log(v.bookId, v.grade + "-" + v.term, "|", u.title, "<-", c.part ?? "", c.title);
}
console.log("근거가 안 보이는 연결:", n);'
```

작업자가 돌렸을 때 **0**이었습니다. 이 점검 자체가 너무 느슨한지도 검토 대상입니다.

## 7. 검토해 주기 바라는 것 (우선순위 순)

1. **거짓 연결 찾기.** 교재의 어떤 장이 엉뚱한 단원에 붙어 있는가.
   특히 b(핵심어)·c(대단원) 규칙으로 붙은 약 570개.
   교육과정 사실이 필요하면 **grok으로 조사하고 본인이 원문을 확인**할 것.
2. **빠진 연결 찾기.** 붙어야 하는데 안 붙은 것. 7번 결함(숫자 단원)처럼 규칙의 사각지대가 더 있는가.
   `data/books/toc-cache.jsonl`에 모든 목차 원문이 있다.
3. **상품 주소 검증.** 210권의 URL이 정말 그 시리즈·학년·학기인가.
   grok으로 표본을 다시 찾아 대조하거나, 4-2를 돌려 전수 확인.
4. **출판사 설명 검증.** `data/books/series.tsv`의 "특징" 칸이 정말 출판사·서점 공식 설명인가,
   아니면 커뮤니티 평가가 섞였는가. 각 시리즈의 예스24 책소개를 grok으로 찾아 대조.
5. **규칙과 화면 설명의 일치.** `/books`의 "억지로 잇지 않았습니다" 문단이 코드가 하는 일과 같은가.
6. **불변 규칙 위반.** 이식 원문 53개가 그대로인가(`tests/ported-content.test.ts`가 지키지만
   테스트 자체가 느슨해지지 않았는지도 볼 것). 콘텐츠 단일 원천이 지켜졌는가.
7. **재현성.** 4-1을 돌렸을 때 `git status`가 깨끗한가.
8. **화면.** 라이트·다크 두 모드, 360px·1280px 두 폭에서 가로 스크롤과 대비(AA)가 유지되는가.

## 8. 보고 형식

발견마다 아래를 갖춰 주세요. **근거 없는 지적은 반영되지 않습니다.**

```
[심각도] 어디 (파일:줄 또는 URL)
무엇이 틀렸나: (한 문장)
근거: (URL과 실제로 읽은 문장, 또는 재현 명령과 그 출력)
```
